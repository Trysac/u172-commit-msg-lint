# Security

## Threat Model

This utility is designed to process text generated by git hooks and user input. The code implements the following defensive boundaries.

### Defended

- **Denial of Service (DoS)**: All operations are gated by `MAX_INPUT_BYTES` (65,536 bytes). Input exceeding this limit immediately raises `CommitLintError` before any parsing logic.
- **Regular Expression Denial of Service (ReDoS)**: The code uses strictly linear regular expression patterns without nested repetition to ensure parsing time complexity is proportional to input length.
- **Information Leakage**: The package uses `logging.NullHandler` to ensure no commit messages or potentially sensitive content are routed to system logs.
- **File Injection**: The CLI restricts file access to the specific path provided as a positional argument.

### Not Defended

- **Untrusted Input**: The validator assumes the provided string is the literal content of a commit message; it does not sanitize against non-malicious but technically invalid UTF-8 byte sequences beyond standard Python decoding.
